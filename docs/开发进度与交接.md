## 二、怎么跑起来

- **启动（用户视角）**：双击项目根目录的 **`启动项目.bat`**。
- **启动（开发者视角）**：命令行里**只跑 `npm run dev` 也行** —— 它会**自动把后端一起带起来**
  （见下面那条 ✅）。
- **地址**：<http://localhost:5173/> —— 打开先是**首页**（`#/`，大字标题 + 「进入学习-->」），
  点按钮才进算法界面（`#/learn`）。⚠️ 路由表一共 5 个页面，**`#/` 是首页、`#/learn` 才是算法界面**
  （最容易按老习惯搞错），详见第四节第 15 条。
- **它同时起两个服务**：

  | 服务 | 端口 | 命令 | 作用 |
  | --- | --- | --- | --- |
  | **后端** | 3000 | `node server/index.mjs`（`npm run server`） | 账号 / 收藏 / 学习记录 / **学习笔记** / 算法元数据（SQLite） |
  | **前端** | 5173 | `vite`（`npm run dev`） | 网页本身（首页 + 算法演示） |

  脚本会**先起后端、等端口通了再起前端**，退出时把 3000 端口一起收掉（避免下次双击端口被占）。
  （命令行直接 `npm run dev` 则是反过来：Vite 先起，再自动把后端拉起来。）
- **管理员账号**：用户名 **`admin`** / 初始密码 **`（已移除的旧口令）`**（第一次启动时自动创建，控制台会打印一行提示）。
  ⚠️ 文档里一律**同时提醒"正式使用请首次登录后改密码"**，别只写账号。
- **跑测试**（两种跑法都用 npm 脚本，别手敲 `node --test` 参数）：

  | 命令 | 跑什么 | 实测读数 |
  | --- | --- | --- |
  | `npm test` | **前后端一起** | Vitest **831 项** + `node:test` **102 个用例** = **933 项** |
  | `npm run test:server` | 只跑后端 | **102 个用例**（`server/test/` 下 8 个测试文件 + 1 个 helpers） |
  | `npm run typecheck` | 类型检查 | 0 错 |
  | `npm run build` | 类型检查 + 生产构建 | 产出 `dist/`（存在时后端会自动同时提供网页和接口） |

  后端用例跑在 **`%TEMP%` 下的临时库 + 随机端口**上，不会碰 `server/data/app.db`，也不会占用 3000。
- **判断启动成功**：黑窗口里先出现后端的 `接口地址 http://127.0.0.1:3000/api` 和 `数据文件 …app.db`，
  再出现前端的 `Local: http://localhost:5173/`。
- ✅ **`npm run dev` 会自动带起后端**（`vite.config.ts` 里的 `algo:auto-start-backend` 插件，只作用于 dev）：
  启动时先用 `node:net` 探一下 3000 —— **已在跑就跳过**（打 `[后端] 已在 3000 端口运行，跳过`），
  没跑就 `spawn(process.execPath, ['server/index.mjs'], { stdio: 'inherit' })` 起一个；
  **Vite 一关就把自己起的那个后端一起收掉**，不留孤儿进程。
  **`启动项目.bat` 依然可用**（它自己先起后端，于是这里走"跳过"那一支，不会重复起）。
  临时想关掉自动启动：`NO_AUTO_SERVER=1 npm run dev`（然后自己 `npm run server`）。
- ⚠️ **只在"手动关掉自动启动"时才会遇到的旧毛病**（`NO_AUTO_SERVER=1 npm run dev`）：
  **算法演示完全正常**（算法在浏览器里跑），但**登录 / 注册 / 收藏 / 学习记录 / 后台全部不可用** ——
  前端请求 `/api/*` 会 404，界面提示"连不上后端服务，请确认后端已经启动"。**这不是 bug，是后端没起。**
- ⚠️ **关掉那个黑窗口服务就停，电脑重启后也必须重新启动一次**（用户遇到过"网页打不开，
  `localhost 拒绝连接`"，原因就是这个，不是代码坏了）。**演示当天务必先双击一次 `启动项目.bat` 预热。**

### 3.1 算法可视化（101 个算法 / 10 个大类）

数据结构与算法的可视化（线性表 / 栈 / 队列 / 数组与矩阵 / 串 / 树 / 图 / **动态规划** / 查找 / 排序）、

6 种渲染器（柱状图 / 顺序表 / 链表 / 通用格子板 / 树 / 网络图）、"上一个 / 下一个算法"（按大类内切换）。

**核心设计**：**算法生成器 yield 语义事件 → 引擎预计算全量步骤序列 → `steps[]` 是唯一真相源**，
代码高亮行和动画状态都从**同一帧**派生，所以"行号与画面不同步"在结构上不可能发生。

**首页**（`#/`）：大字标题 + 一行**从代码算出来的**规模数字 + 「进入学习-->」按钮；**不显示顶栏**，
右上角只放用户区。**空地址 / 乱写地址一律回落首页。**

**⭐ 进入学习界面不默认选中算法**（这一轮修的 bug）：`#/learn` 先进**空状态** ——
「先选一个算法开始学习吧」+ 「看看有哪些算法」按钮，代码 / 动画 / 图例 / 笔记 / 控制条全不显示，
用户选了才出现。原因是那次"默认选中"会被学习记录**当成一次真实学习**写进 `history`
（用户根本没看，却多一条记录），而这类 bug 界面上毫无异常。
**已固化成 6 条常驻回归用例**：`src/stores/learnSelection.spec.ts`
（前 3 条用 `vue/server-renderer` 真渲染 App 核实"没选算法时一个零件都没有"，后 3 条用 spy 核实"一次上报都不发、选了恰好发 1 次"）。

**算法搜索**：选择器顶部搜索框，跨全部大类模糊搜**名称和 id**，↑ ↓ 选 / 回车打开 / **Esc 先清空再关闭**。
逻辑在纯函数 `src/core/algorithmSearch.ts`。**搜索框不放 placeholder 灰字** —— 框前已有 🔍 图标、
输入框保留 `aria-label="搜索算法"`，长灰字只会挤占输入区。

**手动输入数据**：顶栏 ✏️ → `src/components/DataInputDialog.vue`，敲一串数字（如 `5, 2, 9, 1, 7, 3`）喂给当前算法。
校验是纯函数 `src/core/manualInput.ts` 的 `parseNumberList()`：**个数 2~12、每个值 1~999**，非法给中文提示；
合法数据走的是和内置示例**完全相同**的 `buildSteps` 路径。
**⚠️ 这一轮去掉了弹窗里那个可点击的「示例」按钮**：示例在顶部提示和输入框 placeholder 里**已经出现两次**，

## 四、几个容易再踩的坑（都是真实踩过的，现在**都还有效**）

> 已逐条复查：下面每一坑**在今天的代码上都还成立**，**没有过期条目需要删**。
> 其中第 13 条里的用例数字按实测更新过；第 3、3.3、12、13、16、17、18 条涉及的那几处代码
> （`.notes-wrap` / `nullOn401` / `requireAdmin` / `withAvatar` / `ensureColumn` /
> `ON CONFLICT(algo_key)` / 注册表 101 == 种子 101）在本轮校订时**逐个 grep 复核过**。第 2、4、5 条
> 属于"设计约定"，现状就是它们描述的样子（子类只有相邻才合并 / 快照逐字段复制 / 断言带守卫）。

1. **统计口径**：`grep "id: '"` 会**少数 4 个** —— `treeSearch.ts` 里 4 个 AVL 是用
   `avlSpec(...)` 模板生成的（而且链表文件里的结点 id 会被一起数进去，实测能数出 101 个，纯属误导）。
   数算法要用 `algorithmRegistry.length`；数子类 / 渲染器也要从注册表去重，不要数文字。
2. **子类只合并相邻同名组**：`getGroupedByCategory` 只合并**注册表里挨着**的同名 group。
   同名但被别的组隔开，选择器会显示**两个同名标题**（「分配类排序」就这样裂过）。
   所以分组等于**顺便规定了注册顺序**。
3. **`renderer: 'array'` 也能挂板子**：CanvasPanel 支持"柱状图 + 下方板子"。
   计数排序的计数数组、基数排序的桶都靠这个。动态规划的二维表则是 `scene` + `layout: 'grid'`。
4. **快照必须复制**：`[...a]`、`keys: [...n.keys]`。漏了的话"上一步"会看到被后续步骤改过的
   同一份数据（这个坑踩过两次，换字段又踩一次）。
5. **测试可能"静默空跑"**：按组名 / 字符串筛选的断言，条件一改就可能筛出 0 条 ——
   **测试全绿但一条都没执行**。所以这类断言都要配一条"至少覆盖 N 个"的守卫。
6. **改中文 `.md` 只用 read/edit/write 工具，绝不用 PowerShell**（见 `AGENTS.md` 第 2 条）。
   批量替换用**按 UTF-8 读写**的 Node 脚本。
7. **机器散热有问题**（**待机 20W 就跑 79℃**，还因为过热黑屏过一次），所以验证手段要省着用 ——
   建议**清灰 + 换硅脂**。详见本文第 5.3 节与 `AGENTS.md` 第 4 条。
8. ⭐ **数据库文件在 `server/data/app.db`，已被 gitignore**（整个 `server/data/` 目录都不进版本库）。
   **删掉它，下次启动会自动重建**：重新建 6 张表、重新写入 `admin / （已移除的旧口令）`、重新从
   **前端注册表**导入 101 条算法元数据（`db.mjs` 里的 `seededAlgorithms`）。
   代价是**算法元数据会重置成种子状态** —— 在后台改过的名称 / 难度 / 上下架全部丢失，
   而用户、收藏、学习记录、**笔记**（`notes` 表）也一起没了。所以**别随手删它**。
   （附带一句：WAL 模式，所以同目录还有 `app.db-wal` / `app.db-shm`，那是它的正常尾巴，不是垃圾文件。）
9. ⭐ **`src/api/client.ts` 是正式交付文件，不要删 / 不要覆盖。** 它出过事故：一个子代理
   需要在这个路径上做类型检查，就在同一路径建了个临时占位文件；后来正式实现也写在同一个路径上，
   清临时文件时**把正式实现一起删了**，而那时它**还没提交**（`git status` 里只是"未跟踪"），
   **无法从 git 恢复**，只能按《用户与管理员系统设计》的接口契约重写。
   现在文件头第一行注释就写着"这是正式实现，不是临时占位文件，请勿删除"。详见
   《问题与修复记录》第五部分第 6 条。
   **推论**：不要在别人负责的路径上放临时文件；**未提交的文件等于不存在**，做完一件事就提交。
10. **算法元数据在数据库里，算法代码在前端注册表里，两边靠 `algo_key` 对应。**
    后端**不认识算法**、也不存算法代码，它只存"名称 / 大类 / 子类 / 难度 / 简介 / 是否上架 / 排序号"。
    收藏表与学习记录表也是按 `algo_key` 关联（不是 `algorithms.id`），因为前端认的是 `algo_key`。
    后果：**在后台新增一个 `algo_key` 不在前端注册表里的算法，前端不会因此多出一个算法**（只有元数据，没有代码）。
11. **`algorithms.category` 存的是大类 id**（`sort` / `linear` / `stack` / `queue` / `matrix` / `string` /
    `tree` / `graph` / `dp` / `search`），**不是中文名**。接口对中文名是宽容的（会归一化成 id），
    但直接看数据库时别以为存错了。
12. **后端接口失败返回的是中文 `error`，前端直接把它显示给用户。**
    所以后端的错误文案就是用户看到的文案 —— 改后端提示语等于改界面文案，要按给用户看的语气写。
    唯一的例外是 `GET /api/auth/me`，而且**必须把"后端行为"和"前端封装行为"分开说**：
    **后端**未登录 / 令牌失效时照常返回 **401 + 中文"请先登录"**；是**前端** `src/api/client.ts`
    的 `nullOn401` 参数把这个 401 转成 `null`、并清掉本地那个已经失效的令牌，store 启动时靠这个
    `null` 静默判断"没登录"，界面因此不弹错误。
13. **权限在服务端查，前端藏按钮不算数。** 管理员 8 个接口每个都走 `requireAdmin`；
    另外别把"不能删自己 / 不能删掉最后一个管理员"当作前端逻辑 —— 它们都在 `server/api.mjs` 里。
    **这些规则现在有自动化用例了**（`server/test/permissions.node-test.mjs`，**11 个用例**），
    动它们之前先跑 `npm run test:server`；而且**必须同时保住"该放行的也放行了"那一半**
    （见《问题与修复记录》三 · 4：只测"拦得住"是不够的）。
14. **开发时代理**：前端只请求 `/api/xxx`，由 `vite.config.ts` 的 `server.proxy` 转发到 3000，
    所以浏览器看到的是同源请求、不需要 CORS。**后端自己的路由表里路径不带 `/api` 前缀**
    （`index.mjs` 会把前缀剥掉再交给 `api.mjs`），加接口时别把前缀写两遍。
15. ⚠️ **前端路由表一共 5 个页面：`#/` 是首页，算法界面在 `#/learn`**（最容易被"老习惯"搞错）：
    - `#/` **首页**（大字标题 + 「进入学习-->」按钮；**首页不显示顶栏**，右上角只放一个用户区）
    - `#/learn` **算法学习界面**（加首页之前，它就是 `#/`）
    - `#/favorites` **我的收藏 + 学习记录**
    - `#/report` **我的学习报告**（`d02940f` 新增）：顶栏右侧「📊 学习报告」按钮进来
    - `#/admin` **管理员后台**
    - **空地址 / 写错、乱写的地址一律回落首页**（`normalizeHash()` 会把地址栏也归位到 `#/`），
      **不是**算法界面
    - 所以代码里"去看算法"一律 `navigate('/learn')`；新加页面、写跳转时别顺手写 `navigate('/')`。
    - 路由表就在 `src/router.ts` 一个文件里（**99 行**，`routeNameFromHash` / `ROUTE_PATHS` / `TITLES`），
      加页面要**三个地方一起加**。
16. **`users.avatar` 是新增的列，加列方式是幂等 `ALTER TABLE`**（`server/db.mjs` 的 `ensureColumn`）：
    先 `PRAGMA table_info(users)` 看这列在不在，**缺了才 `ALTER TABLE ... ADD COLUMN`**，
    **不删表、不重建**。真实的 `server/data/app.db` 已经就地升过级了。
    另外**返回的用户对象现在是 7 个字段**（多了 `avatar`，没设置是 `null`），改用户对象形状时
    `server/api.mjs` 里 `withAvatar()` 经过的那几个出口要一起改。
17. ⭐ **算法种子是"幂等补齐"，不是在后台删掉就完事。** `server/db.mjs` 的 `seedAlgorithms()`
    每次启动都跑一遍，用的是 `INSERT ... ON CONFLICT(algo_key) DO NOTHING` + 一条只改
    `sort_order` 的 UPDATE。三条后果都要记住：
    - **只补缺的、绝不覆盖** —— 管理员在后台改过的名称 / 大类 / 子类 / 难度 / 简介 / 上下架
      **一个都不会被种子改回去**（别"顺手优化"成 upsert 覆盖）；
    - **后台删掉一个"种子里的"算法，下次启动会被补回来** —— 想**永久隐藏某个算法，请用「下架」
      而不是「删除」**。删除只在"这个算法不在种子里（管理员自己加的）"时才是持久的；
    - **`sort_order` 是派生值**，等于它在**前端注册表里的下标**。往后端种子里插新算法时，
      重排那一步不能省 —— 否则老库会出现"新旧算法抢同一个 `sort_order`、列表顺序乱掉"。
    （实测：老库原来 98 条，动态规划那次启动自动补进 3 条 → 101 条。）
18. ⭐ **前端注册表（101）和后端种子（101）必须一致 —— 加算法要"两边都加"。**
    两边是两份**手工维护**的清单：前端 `src/algorithms/index.ts`（算法代码在这），
    后端 `server/db.mjs` 的 `SEED_ALGORITHMS`（元数据快照在这）。后端是 `.mjs`、前端是 `.ts`，
    运行时谁也读不到谁，**没有任何机制会自动同步**。
    **收尾时专门核过这一对数字（现在两边都是 101，`algo_key` 集合与顺序完全一致）。**
19. **后端改了必须重启后端进程。** 后端是 `node server/index.mjs`，**没有热重载**：
    改了 `server/*.mjs` 之后如果后端是 `npm run dev` 自动带起来的，它会一直跑着那份旧代码。
    **改完后端关掉重起一次**（或 `NO_AUTO_SERVER=1` + 手动 `npm run server` 看日志调）。前端不用——Vite 有 HMR。
20. **笔记是"一个用户对一个算法只有一条"，空内容等于删除。** `notes` 表的主键是
    `(user_id, algo_key)`（不是自增 id），所以：对同一个算法再写一次是**更新**（`PUT /notes/:algoKey`）；
    **内容清空（或全空白）= 删掉这条笔记**，不是存一条空字符串。和其它表一样按 `algo_key` 关联。
21. **改中文文档之后要做"编码体检"**：用 Node 检查 8 份 `.md` 里的 `U+FFFD`（无法识别的替换字符）必须为 **0**，
    并 grep 一遍陈旧数字（"43 次""d02940f""824""5 张表"当当前值用……），
    **区分"历史读数"（保留并写明）和"当前值"（要改）**。

## 七、这一轮校订顺手记下的四条教训（值得记进流程）

1. **并行开发时，"跨两端的数字 / 枚举"是没人拥有的。**
   5 个功能是并行做的，其中动态规划那批**只改了前端** → 前端 101 / 后端种子 98，
   大类白名单里也漏了 `dp`。两端各自的代码都是对的，**错的是"这两端是否一致"没人负责**。
   所以收尾清单里要**显式加一条**：前端注册表条数 == 后端种子条数、两边 `algo_key` 集合与顺序一致、
   大类枚举两处都有。（详见《问题与修复记录》六 · 1。）
2. **"默认行为"也会被记成数据。** 进学习界面时"默认帮你选一个算法"看起来只是个小方便，
   但它会**在数据库里留下一条用户没做过的学习记录** —— 界面上毫无异常。
   现在这条有 6 条常驻回归用例守着；**凡是"界面自动做了什么"，都要问一句"这件事会不会被记下来"。**
3. **能点的东西必须明确比不点更好。** 手动输入弹窗里那个「示例」按钮，能点、但只会
   **覆盖用户已经敲进去的内容**，而它提供的示例用户已经看见两次了 —— 所以去掉。
   顺着这条思路，算法搜索框也去掉了那段很长的 placeholder 灰字（图标 + `aria-label` 已经够了）。
   这两处都是**纯界面取舍**，没有自动化用例，靠人眼核对。
4. **文档校订要区分"历史读数"和"当前值"。** 同一份文档里"当年是 98 个算法"和"现在是 101 个算法"
   必须能一眼分开 —— 前者要**保留并写明是当时读数**，后者要改。这一轮校订就是按这条做的
   （grep 出来的几十处命中，**逐条判断后只改了"当前值"的那些**，历史读数一律保留）。
   额外一条经验：**"X → Y"这种叙述里的中间值如果写错了（比如把 54 写成 86），也要改** ——
   它不影响当前口径，但会被细心的读者抓住，而它本来就不该错。
