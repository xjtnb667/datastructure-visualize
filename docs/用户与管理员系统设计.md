> 这份文档是**接口契约**：后端、用户端、管理端三块并行开发，都按它来，不要各自发挥。
> 也用于讲解时解释"系统部分是怎么做的"。

## 一、为什么这么做（设计口径）

原来这个平台是**纯前端**（所有算法跑在浏览器里）。加上用户和管理员之后，它变成了
**前后端分离的系统**：

```
浏览器（Vue 3）  ──HTTP/JSON──►  Node 后端  ──SQL──►  SQLite 数据库（一个文件）
```

**技术选型的三条理由**（都能被追问）：

1. **数据库用 SQLite，不用 MySQL** —— 它是一个**单文件数据库**，不用单独安装、不用配服务，
   但**是真正的数据库**（支持 SQL、事务、索引）。对一个"要求双击就能跑起来"的交付物，
   它比 MySQL 更合适；换成 MySQL 只要改连接方式，SQL 基本不用动。
2. **后端只用 Node 自带的能力**（`node:http` / `node:sqlite` / `node:crypto`），
   **没有引入任何新的第三方包** —— 依赖越少，出问题的环节越少。
3. **密码不存明文**：用 `crypto.scrypt` 加盐哈希（每个用户一个随机盐）。
   数据库文件被别人拿到也**算不出原始密码**。

## 三、数据库表

```sql
-- 用户
CREATE TABLE users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  username      TEXT NOT NULL UNIQUE,        -- 用户名（登录用）
  nickname      TEXT NOT NULL,               -- 昵称（显示用）
  password_hash TEXT NOT NULL,               -- scrypt 哈希
  salt          TEXT NOT NULL,               -- 每个用户一个随机盐
  role          TEXT NOT NULL DEFAULT 'user',-- 'user' | 'admin'
  disabled      INTEGER NOT NULL DEFAULT 0,  -- 1 = 被管理员禁用
  created_at    INTEGER NOT NULL,
  avatar        TEXT                         -- 自定义头像：图片的 data URL；NULL = 没设置（界面显示昵称首字）
);

-- 会话令牌（登录后发一个随机串，前端存着，每次请求带上）
CREATE TABLE sessions (
  token      TEXT PRIMARY KEY,
  user_id    INTEGER NOT NULL,
  created_at INTEGER NOT NULL,
  expires_at INTEGER NOT NULL
);

-- 算法元数据（管理员可增删改查的部分；算法本身的代码仍在前端注册表里）
CREATE TABLE algorithms (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  algo_key   TEXT NOT NULL UNIQUE,   -- 对应前端注册表里的 id，如 'bubble-sort'
  name       TEXT NOT NULL,
  category   TEXT NOT NULL,
  grp        TEXT,                   -- 子类名（注意 group 是 SQL 关键字，用 grp）
  difficulty INTEGER NOT NULL DEFAULT 2,  -- 1 入门 / 2 中等 / 3 较难
  summary    TEXT,                   -- 一句话简介
  online     INTEGER NOT NULL DEFAULT 1,  -- 1 = 上架，0 = 下架（前端不显示）
  sort_order INTEGER NOT NULL DEFAULT 0
);

-- 收藏
CREATE TABLE favorites (
  user_id    INTEGER NOT NULL,
  algo_key   TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  PRIMARY KEY (user_id, algo_key)
);

-- 学习记录（每个用户对每个算法只留一条，累加）
CREATE TABLE history (
  user_id      INTEGER NOT NULL,
  algo_key     TEXT NOT NULL,
  views        INTEGER NOT NULL DEFAULT 0,  -- 打开过几次
  max_step     INTEGER NOT NULL DEFAULT 0,  -- 最多看到第几步
  total_steps  INTEGER NOT NULL DEFAULT 0,  -- 这个算法一共几步（最后一次看到的）
  updated_at   INTEGER NOT NULL,
  PRIMARY KEY (user_id, algo_key)
);

-- 学习笔记（用户自己对某个算法的理解 / 易错点；一段纯文本，支持多行）
CREATE TABLE IF NOT EXISTS notes (
  user_id    INTEGER NOT NULL,
  algo_key   TEXT NOT NULL,               -- 前端注册表里的算法 id，如 'bubble-sort'
  content    TEXT NOT NULL,               -- 正文（去首尾空白后存；1~2000 字）
  created_at INTEGER NOT NULL,            -- 第一次写这条笔记的时间（更新时不动它）
  updated_at INTEGER NOT NULL,            -- 最后一次保存的时间（界面上"最后修改"）
  PRIMARY KEY (user_id, algo_key)         -- 一个用户对一个算法**只有一条**：写第二次就是更新
);
```

### 表结构升级：加列**绝不删表重建**（`users.avatar` 就是这么加的）

交付物是"用户已经在用的那个库"，里面已经有账号、收藏、学习记录和 101 条算法元数据，
所以加字段**不能**用"删表重建 / 删库重建"这种办法（那等于把用户数据清空）。做法只有一句
（`server/db.mjs` 的 `ensureColumn`）：

```
PRAGMA table_info(users)  ->  看 avatar 在不在  ->  不在才 ALTER TABLE users ADD COLUMN avatar TEXT
```

于是它在三种情况下都安全，而且**可以反复执行**（幂等）：

| 打开的是哪种库 | 这段代码的行为 |
| --- | --- |
| 全新库（第一次启动） | 上面的 `CREATE TABLE` 已经带了 `avatar`，这里**什么都不做** |
| 老库（表是旧结构、没有 `avatar`） | 补一次 `ALTER TABLE ADD COLUMN`，**已有数据一行不动**（老用户的 `avatar` 就是 `NULL`） |
| 已经升过级的库 | 同样什么都不做（再启动多少次都一样） |

**新增一张表也是同样的道理**：`notes` 是后加的功能，老库里根本没有它，
所以它用 `CREATE TABLE IF NOT EXISTS notes (...)` 建 ——
新库建、老库也建，**不删表、不重建、不动已有的 5 张表**（加 `notes` 之前库里就是 5 张业务表，现在是 6 张），
重复启动多少次结果都一样。
也就是说"加列"和"加表"都不需要用户做任何事，也不会丢数据
（真实库的验证方式见 `server/test/avatar-migration.node-test.mjs` 与
`server/test/notes.node-test.mjs`：后者全程跑在 `%TEMP%` 的临时库上，一行都不碰 `server/data/app.db`）。

表名 / 列名是本文件里的字面量常量，不是用户输入，所以这里拼 SQL 是安全的；
**其余 SQL 一律参数绑定**（见第五部分第 5 条）。证明方式见
`server/test/avatar-migration.node-test.mjs`（**6 个用例** —— 加头像时是 5 个，后来加笔记功能时又补了一条"老库顺带补齐缺的算法种子"）和《问题与修复记录》五 · 9。

**种子数据**：启动时自动建表，并写入一个管理员账号
（用户名 `admin`，初始密码 `（已移除的旧口令）`，首次登录后可在后台改密码）和一批算法元数据
（101 条，与 `src/algorithms/index.ts` 的注册表一一对应 —— 后端不重复维护算法清单）。

**种子是"补齐式"的，不是"只在空库时写一次"**（`server/db.mjs` 的 `seedAlgorithms`）：
按 `algo_key` 逐条 `INSERT ... ON CONFLICT(algo_key) DO NOTHING` ——
**缺的补进来，已有的一个字都不改**（管理员在后台改过的名称 / 大类 / 子类 / 难度 / 简介 /
上架状态全部保留，收藏 / 学习记录 / 笔记也不受影响），并且用一条只改 `sort_order` 的
`UPDATE` 把种子这些行的排序号对齐到注册表下标。于是前端注册表新增算法时，
**已经在用的老库不用做任何事**：下次启动就把新的那几条补进算法表
（动态规划那 3 条就是这么进来的：98 → 101），不删表、不重建。
💡 一个要记住的推论：在后台**删掉**一个种子里的算法（`algo_key` 在种子里），
下次启动后端会把它**补回来**（只有元数据，前端注册表里本来就有它的代码）——
"永久隐藏"某个算法请用**下架**（`online = 0`），不要用删除。

**大类白名单**：算法的大类（`algorithms.category`）是**固定的 10 个**，
`server/api.mjs` 的 `CATEGORY_NAMES` 就是白名单 ——
`linear` 线性表 / `stack` 栈 / `queue` 队列 / `matrix` 数组与矩阵 / `string` 串 /
`tree` 树与二叉树 / `graph` 图 / **`dp` 动态规划** / `search` 查找 / `sort` 排序。
它和前端 `src/core/categories.ts` 的 `CATEGORIES` 必须**同步**（后台的大类下拉就是照前端渲染的），
改一边就要改另一边：少一个大类，管理员在后台新增 / 修改这类算法会被 **400** 拒绝
（错误文案里会列出允许的大类）。接口对中文名是宽容的（传「动态规划」会归一化成 `dp`）。

## 四、接口（全部以 `/api` 开头，请求响应都是 JSON）

**一共 23 个**：认证 4 / 用户功能 10（收藏 3 + 学习记录 2 + **学习笔记 4** + 改自己资料 1）/ 管理员 8 / 公开 1。
权威清单是 `server/api.mjs` 末尾的 `ROUTES` 数组；前端 `src/api/client.ts` 里是逐条对应的 23 个函数。

约定：
- 需要登录的接口，请求头带 `Authorization: Bearer <token>`
- 成功：`{ ok: true, data: ... }`
- 失败：`{ ok: false, error: "给用户看的中文说明" }`，HTTP 状态码同时给对（400/401/403/404/409）

### 认证
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/register` | 入 `{username, nickname, password}`；用户名重复返回 409 |
| POST | `/api/auth/login` | 入 `{username, password}`；被禁用返回 403 |
| POST | `/api/auth/logout` | 需要登录，作废当前令牌 |
| GET | `/api/auth/me` | 需要登录，返回当前用户 |

返回的用户对象一律**不含** `password_hash` / `salt`，**一共 7 个字段**：

```ts
{ id, username, nickname, role, disabled, created_at, avatar }
// avatar: string | null —— 图片的 data URL；没设置就是 null（界面显示昵称首字）
```

注册、登录、`GET /api/auth/me`、`PATCH /api/auth/me`、以及管理员接口里返回的用户对象
（`GET /api/admin/users` 的列表项、`PATCH /api/admin/users/:id` 的返回值）**形状完全一致**，
都带 `avatar`。实现上认证模块的 `publicUser()` 是白名单式的（不含 `avatar`），
所以 `server/api.mjs` 统一用 `withAvatar()` 给这些出口补上这一列 —— **改用户对象的形状时，
这几个出口要一起改**。

### 用户功能（都需要登录）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/favorites` | 我的收藏 → `{ algo_key, created_at }[]` |
| POST | `/api/favorites` | 入 `{algoKey}`，重复收藏返回 409 |
| DELETE | `/api/favorites/:algoKey` | 取消收藏 |
| GET | `/api/history` | 我的学习记录 → `{ algo_key, views, max_step, total_steps, updated_at }[]` |
| POST | `/api/history` | 入 `{algoKey, step, totalSteps}`；`views` +1、`max_step` 取较大值 |
| GET | `/api/notes` | **我的全部笔记** → `{ algo_key, content, created_at, updated_at }[]`（按 `updated_at` 倒序，最近改的在前） |
| GET | `/api/notes/:algoKey` | 某一个算法的笔记；**没写过返回 `200 { ok: true, data: null }`，不是 404**（"还没写"是正常状态，不该让前端当错误处理） |
| PUT | `/api/notes/:algoKey` | 新增或更新（入 `{content}`）；保存成功返回**写进去的那条**（含服务端时间戳）；`content` 去空白后为空 = **删掉这条笔记**并返回 `data: null`；超过 2000 字返回 400 |
| DELETE | `/api/notes/:algoKey` | 删除（**幂等**：没写过也返回成功）→ `data: null` |
| PATCH | `/api/auth/me` | 改自己的昵称 / **头像** / 密码（入 `{nickname?, avatar?, oldPassword?, newPassword?}`）；**改密码会作废该用户在其它设备上的会话，当前设备保持登录**（只改昵称不影响其它设备）；`avatar` 传 data URL = 设置、传 `null` 或 `''` = **清除**（校验规则见下面「头像字段」） |

### 学习笔记（`notes`）的契约

一段**纯文本**（前端是 `<textarea>`，支持多行；**不渲染 Markdown**，原样显示 ——
笔记是给自己看的草稿，不引 Markdown 库也就没有额外的 XSS 面）。

| 规则 | 具体内容 |
| --- | --- |
| **都要登录** | 4 个接口未登录一律 **401 +"请先登录"** |
| **只能读写自己的** | `user_id` **一律取自令牌**（`requireAuth` 解析出来的用户），**绝不从请求体 / 查询串里取**；每条 SQL 都带 `WHERE user_id = ?`。所以即使用户在请求体里塞 `user_id` / `userId`，也只写到自己名下 |
| **一个用户一个算法一条** | 表主键 `(user_id, algo_key)`，写第二次是 `UPDATE`（`created_at` 保持第一次的时间，只动 `content` / `updated_at`） |
| **长度上限** | `content` 去首尾空白后 **≤ 2000 字**；超了 **400** + 中文说明（`笔记太长了：最多 2000 个字，当前 2001 个字`）。存的是**去掉首尾空白**的内容，所以"2000 字 + 一圈空格"也算合法 |
| **类型校验** | `content` 必须是字符串；缺参数 / `null` / 数字 / 对象 / 数组一律 **400**（`缺少参数 content：笔记内容必须是字符串`），且**一个字都不落库** |
| **空内容 = 删除** | 去空白后是空串（`''` 或纯空白）= 删掉这条笔记，**这是合法输入不是错误**（`PUT` 返回 `data: null`） |
| **读不存在的不是错误** | `GET /api/notes/:algoKey` 返回 `data: null`（HTTP 200）；`DELETE` 删不存在的也返回成功（幂等） |
| **算法标识** | 和收藏 / 学习记录一致：去空白后 1~64 个字符，超了 400 |
| **连带清理** | 管理员**删除用户**时连他的笔记一起清；**删除算法**时连这个 `algo_key` 下的笔记一起清（否则以后同 key 的算法会看到旧笔记） |

用例见 `server/test/notes.node-test.mjs`（**15 个**：4 个接口未登录 401、全流程、
空内容 = 删除、2001 字被拒且不落库、正好 2000 字可以写、数据隔离（A 的笔记 B 看不到 /
改不了 / 删不掉）、请求体里塞 `user_id` 也伪造不了、读不存在返回 null 不是 404、
删除幂等、按最近修改倒序、删用户 / 删算法连带清理、临时库隔离）。

**改密码的会话作废规则**（`PATCH /api/auth/me`，实现见 `server/api.mjs` 的 `authUpdateMe`）：

- **改密码成功** → 该用户在**其它设备**上的登录**立刻失效**（那些设备下次请求收到 401，前端提示"登录状态已失效，请重新登录"）；
  **当前这台设备保持登录**（用户刚用原密码证明了自己是谁，不该把自己踢下线）。
  实现就是一句 `DELETE FROM sessions WHERE user_id = ? AND token != ?`（`token` 取当前请求头里的那个）。
- **只改昵称** → 不动任何会话，**其它设备不受影响**（昵称不是凭据）。
- 对比：管理员**重置别人的密码**（`PATCH /api/admin/users/:id` 带 `password`）是**把那个人的全部会话一起清掉，
  包括他正在用的那台** —— 管理员重置的不是自己的密码，没有"保留当前设备"的理由；**禁用**该用户同理。

### 头像字段（`avatar`）的契约 —— 服务端把关，**非法一律 400 且不落库**

`avatar` 的值会**原样回给前端、塞进 `<img src="...">`**，所以这里**不能"随便存个字符串"**。
服务端校验在 `server/api.mjs` 的 `assertAvatar()`（`PATCH /api/auth/me` 和
`PATCH /api/admin/users/:id` 两条路都走它，规则一字不差）：

| 规则 | 具体内容 |
| --- | --- |
| **格式** | 必须匹配 `^data:image/(png\|jpeg\|jpg\|webp\|gif);base64,`（即"图片的 data URL"），前缀后面才是 base64 正文 |
| **正文** | 必须匹配 `^[A-Za-z0-9+/]+={0,2}$`（真的是 base64，不能把 HTML / 脚本塞在正文位置） |
| **大小** | base64 正文长度 **≤ 200KB**（`200 * 1024` 个字符；前端上传的是 128×128 的 JPEG，正常只有几 KB，这条挡的是"往数据库里塞几 MB"） |
| **清除** | 传 `null`（或 `''` / 只有空白的字符串）＝ **清除头像**，库里存 `NULL`，**这是合法输入、不是错误** |
| **类型** | 必须是字符串或 `null`；数字 / 布尔 / 对象 / 数组都是 **400** |

**明确不接受的东西**（都会被 400 拒掉，并且**数据库里一个字都不写**）：

- **SVG（`data:image/svg+xml;...`）** —— SVG 里能内嵌脚本，同源下等于给所有人开了一个存 XSS 载荷的地方；
- `javascript:` 之类的伪协议、普通网址（`https://...`）、HTML 片段、纯文本；
- 只有 base64 正文、没有 `data:image/...;base64,` 头的字符串；
- 头对了但正文非法（比如把 HTML 直接塞在 base64 位置）、或者头对了但内容为空。

失败返回 **400 + 中文说明**（`{ ok: false, error: "…" }`），文案按"给用户看"写，例如
「头像格式不对：只支持 PNG / JPEG / WebP / GIF 图片」「头像内容不是合法的 base64 图片数据」
「头像太大了：压缩后的图片不能超过 200KB，请换一张小一点的图片」。
用例见 `server/test/avatar.node-test.mjs`（26 个用例，含"非法内容没写进库"的断言）。

**前端压缩的效果（开发时实测）**：一张 **2.84MB** 的手机照片，经过上面那套"居中裁方 → 128×128 → JPEG(0.85)"
之后，上传的 data URL **约 9.7KB** —— 比原图小约 **300 倍**。这也是为什么 200KB 的上限"非常宽松"：
正常路径下根本碰不到它，它挡的是"绕过前端直接往数据库里塞几 MB"。

## 五、权限与安全（要写在代码里，不只是文档）

1. **密码**：`scrypt(password, salt, 64)`，盐是每个用户 16 字节随机值；比对用 `timingSafeEqual`。
2. **令牌**：32 字节随机 hex，有效期 7 天；每次请求校验存在性和过期时间。
3. **越权防护**：
   - 管理员的每个接口都要**先查角色**，不能只靠前端隐藏按钮
   - 删除用户时**不能删自己**、**不能把最后一个管理员删掉或降级**（否则系统锁死）
   - 用户只能操作**自己的**收藏、学习记录**和学习笔记**（`user_id` 从令牌来，不从请求里取）
4. **入参校验**：用户名 3~20 字符（字母数字下划线）、密码至少 6 位；**头像必须是图片的 data URL
   且正文 ≤ 200KB（`null` / `''` = 清除）**，非法一律 400 且不落库（详见第四部分的「头像字段」）；
   **笔记正文必须是字符串、去空白后 ≤ 2000 字**（空 = 删除，见第四部分的「学习笔记」）；
   所有写接口都要校验，错误返回中文说明。
5. **SQL 一律用参数绑定**（`db.prepare(...).run(?)`），**不做字符串拼接**，防注入。
6. **会话生命周期（改密码 / 禁用之后旧令牌立刻不能再用，不是等到 7 天过期）**：
   - **改自己的密码**（`PATCH /api/auth/me`）：作废该用户在**其它设备**上的会话，**当前设备保留**；
     **只改昵称不清会话**（昵称不算凭据变了）。
   - **管理员重置别人的密码 / 禁用某个用户**（`PATCH /api/admin/users/:id`）：**把那个人的全部会话一起清掉**，
     包括他当前正在用的那条；删除用户时也一并清掉。
   - **退出登录**只作废当前这一个令牌；令牌到期的判断照第 2 条。
   - 被清掉会话的设备下次请求得到的是 **401 +"请先登录"**，前端由 `nullOn401` 转成"未登录"并清掉本地失效令牌。

## 六、前端行为

- **首页（落地页，`#/`）**：一行大字「算法可视化平台」+ 副标题 + 一行规模数字 + 「**进入学习-->**」按钮
  （点了去 `#/learn`）。**首页不显示顶栏**（logo + 算法选择器 + 数据规模那一整条）——
  落地页要干净，而且还没进算法界面时那些选择器没有意义；但**右上角保留用户区**
  （`<UserMenu />` 单独放一个），否则游客在首页没法登录。规模数字**从代码里数出来**
  （`CATEGORIES.length` / `algorithmRegistry.length`），不是写死的文案。
- **游客**：能看所有算法和动画（和现在完全一样）。点收藏 → 弹登录框。
- **登录后**：顶栏右上角显示头像 + 昵称 + 下拉菜单（我的收藏 / 学习记录 / **学习报告** / **更换头像** / 退出；管理员多一项"后台管理"）。
- **头像**：顶栏那个 24px 的圆，**有自定义头像就显示图片，没有就显示昵称第一个字**；
  下拉菜单里的「更换头像」打开 `AvatarDialog.vue` ——
  选图后**在浏览器里用 canvas 居中裁成正方形 → 缩到 128×128 → 导出 JPEG（质量 0.85）**再上传。
  所以进数据库的是压缩后的小图（正常几 KB），原图几 MB 也不会把库撑大；
  这一步**不需要任何图片处理库**（`FileReader` / `Image` / `canvas` 都是浏览器自带的）。
  弹窗里还有「恢复默认」（传 `null` 清除头像，恢复成昵称首字）。
- **收藏**：算法面板的标题栏加一个星标按钮，点亮/取消；状态存在后端。
- **学习记录**：切换算法时上报一次（`views` +1）；步骤前进时**节流上报**（比如每 5 步或每 2 秒一次），
  不要每一步都发请求。
- **学习笔记**（`components/NotesPanel.vue` + `stores/notes.ts`）：给**当前这个算法**写自己的笔记。
  - **位置在左栏、代码框正下方**（`App.vue` 里的 `.notes-wrap`）：宽度天然等于代码框，
    **不再占用右栏动画区的高度**（以前它是整行挂在"代码 / 动画"两块面板下面，会从整页高度里切走一条）。
    面板整体 `max-height: 32vh`、输入框 `56px ~ 18vh`（窄屏 30vh / `52px ~ 16vh`），超出由面板内部滚动，
    所以笔记写得再长也不会把代码框压没。
  - 面板只有一个属性 `algoKey`（当前算法的 id），内部跟着它变：换算法就换成那个算法的笔记，
    没写过就是空白可直接写；纯文本多行 `<textarea>`，右下角显示「n / 2000 字」和「最后修改」时间，
    保存成功给一个 2 秒的「已保存」小提示；删除按钮要点两次（第一次只是问一句）。
  - **未登录**：面板显示一句提示 + 「登录 / 注册」按钮。**store 自己不弹登录框** ——
    `saveNote` / `removeNote` 只回一个 `{ status: 'login' }` 信号（和收藏的 `toggleFavorite` 一个套路），
    弹窗由界面决定；`NotesPanel.vue` 内嵌了一个 `AuthDialog`，所以父组件挂上就能用、不需要额外接线。
  - **乐观更新 + 失败回滚**：点保存立刻能看到结果（本地先写进 `Map<algo_key, note>`），
    请求失败就退回原样并显示后端的中文错误；令牌失效（401）时回 `{ status: 'login' }`
    并清空本地笔记，界面切成"请重新登录"。
  - 登录后拉一次全部笔记（`Map<algo_key, note>`，查某个算法是 O(1)）；下拉取**静默失败**，
    后端没启动也不打断看动画；**退出登录立刻清空本地笔记**，别让下一个人看到。
- **学习报告**（`views/ReportView.vue` + `core/report.ts`，地址 `#/report`）：**需要登录**。
  - 数据来源**两处**：后端的 `GET /api/history`（原始学习记录）+ 前端 `algorithmRegistry`（算法的总数与归类）。
  - **口径全部在 `core/report.ts` 的纯函数 `computeReport()` 里**，`ReportView.vue` 只负责画：
    **学过 = `max_step >= 2`**（第 1 步是初始帧，打开不算学过）、
    **覆盖率 = 学过的算法数 ÷ 前端登记表总数**、**完成度 = `max_step / total_steps`（> 100% 按 100% 记）**。
    "打开过但没有真的往下看"的算法算进「最近学习」，但**不计入覆盖率**；管理员在后台加过的、
    前端登记表里没有的算法同样如此（它们只有元数据、没有代码，点不开学）。
  - **图是手画的，没有引入图表库**：覆盖率环是 SVG 圆的 `stroke-dasharray`（几何由纯函数
    `ringGeometry()` 算），大类分布条是 CSS 宽度百分比；颜色来自 `categoryColor()`（和平台图例同一套）。
  - 页面分五块：覆盖率环 / 按 10 个大类的分布 / 打开次数 Top 10 / 最近学习（8 条）/ 看得最完整的几条（8 条）。
  - 因为数字全部来自纯函数，"口径对不对"和"图画得好不好看"可以分开验证 —— 改图不会动口径。
- **算法搜索**（`components/AlgorithmPicker.vue` + `core/algorithmSearch.ts`）：选择器顶部一个搜索框，
  **跨全部大类**模糊匹配算法**名称与 id**；↑ / ↓ 选择、**回车**打开、**Esc 第一次清空搜索、第二次才关面板**。
  匹配逻辑在纯函数 `searchAlgorithms(query)` 里，**不认识界面**（所以能单独核对）；它和登录无关，游客也能用。
- **手动输入数据**（`components/DataInputDialog.vue` + `core/manualInput.ts`）：顶栏 ✏️ 打开，
  自己敲一串数字（如 `5, 2, 9, 1, 7, 3`）喂给当前算法。校验在纯函数 `parseNumberList()` 里
  （**个数 2~12、每个值 1~999**，非法给中文提示）；合法数据走的是和"示例 / 随机数据"**完全相同**的
  步骤序列生成路径，所以受同一套引擎校验保护。同样和登录无关。
  ⚠️ 弹窗里的示例**只作展示、不是按钮**：示例在顶部提示（"例如：`5, 2, 9, 1, 7, 3`"）和输入框的
  `placeholder` 里已经各出现一次，再放一个能点的"示例"按钮既重复，又会在用户只是想看看格式时
  **把已经敲进输入框的内容覆盖掉**。现在只剩「用当前数据」一个快捷按钮。
- **算法搜索框的提示方式**：框前有一个 🔍 图标、输入框上保留 `aria-label="搜索算法"`，
  所以**不放 placeholder 灰字** —— 提示已经由图标 + 无障碍标签承担，灰字只会挤占输入区。
- **进入学习界面（`#/learn`）时的空状态**：**不默认选中任何算法**。没选之前只显示一句
  「先选一个算法开始学习吧」+ 一个「看看有哪些算法」按钮（点了展开顶栏的选择器），
  代码 / 动画 / 图例 / 笔记面板 / 控制条 / 收藏星标**一个都不显示**。
  原因是"默认选中"会被学习记录当成一次真实学习写进 `history`（用户根本没看，却多出一条记录）；
  这条行为由 `src/stores/learnSelection.spec.ts` 的 **6 条常驻回归用例**守着
  （前 3 条真渲染整个 App 核实"没选算法时一个算法零件都没有"，后 3 条用 spy 核实"没选算法时一次上报都不发、选了恰好发 1 次"）。
- **管理员后台**：`#/admin`，两个标签页 —— 用户管理、算法管理，都是表格 + 搜索 + 分页 + 新增/编辑弹窗 + 删除确认；
  用户列表里显示每个人的头像（没设置的显示昵称首字），并且**管理员可以清空某个用户的头像**；
  算法管理里的大类下拉是**照前端 `CATEGORIES` 渲染的 10 项**（含「动态规划」），
  而服务端白名单（`CATEGORY_NAMES`）必须与它一致，否则提交会被 400 拒。
- **路由**：自己写的极简 hash 路由（`src/router.ts`，**99 行**），**不引入 vue-router**，
  保持"零新增依赖"这条线。路由表：

  | 地址 | 页面 |
  | --- | --- |
  | `#/` | **首页（落地页）** |
  | `#/learn` | **算法学习界面**（算法可视化主界面） |
  | `#/favorites` | 我的收藏 + 学习记录 |
  | `#/report` | **我的学习报告**（需要登录） |
  | `#/admin` | 管理员后台（仅管理员） |

  ⚠️ **`#/` 以前就是算法学习界面**，加了首页之后它让给了首页，算法界面搬到 `#/learn` ——
  所以**旧的 `#/` 地址不再直接进算法界面**。**空地址**（第一次打开）和**写错的地址**
  （`#/fav`、乱写）一律**回落首页**（`normalizeHash()` 会把地址栏也归位到 `#/`），不是算法界面。

## 七、启动方式（必须保持"双击一下就能用"）

- 开发：`启动项目.bat` 先起后端（`node server/index.mjs`，端口 3000），再起前端 Vite（端口 5173）；
  Vite 里配 `/api` 转发到 3000。
- 生产：`npm run build` 之后，后端**同时**提供 API 和 `dist/` 静态文件，只用一个端口。
- 用户看到的仍然是：**双击 `启动项目.bat` → 浏览器打开 `http://localhost:5173/`**。
  打开后**先是首页**（`#/`，大字标题 + 「进入学习-->」按钮），点按钮才进算法界面（`#/learn`）。
