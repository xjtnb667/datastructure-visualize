# 算法可视化平台

一个用于《数据结构与算法》教学的可视化演示平台：**左侧显示算法源码并高亮当前执行行，右侧用柱状图动画展示数据变化，两者严格同步**，支持「上一步 / 下一步 / 播放 / 重置」。

**打开先是首页**（`#/`，大字标题 + 「进入学习-->」按钮），点按钮进算法界面（`#/learn`）。
**带用户系统与管理员系统**：游客不用登录就能看全部 101 个算法；注册登录后可以**收藏算法**、平台会记录**学习记录**、可以看自己的**学习报告**（`#/report`）、给算法写**学习笔记**、还能**换自定义头像**；管理员有一个后台页面（`#/admin`），可以管理用户和算法。所以这个项目是**前后端分离**的 —— 浏览器里跑算法，服务器上存账号、收藏与笔记（见下面第五节和《用户与管理员系统-设计.md》）。

**这一轮新加的 5 个功能**（详见下面第三节）：
**动态规划大类**（0-1 背包 / 最长公共子序列 / 编辑距离，二维表格一格一格填出来 —— **没有新增渲染器**，复用画矩阵那一套）、
**学习报告页**（覆盖率环 + 大类分布 + Top 10 + 最近学习，**图表全是 SVG / CSS 手画，没用图表库**）、
**算法搜索框**（跨全部大类搜名称和 id，↑ ↓ 选择、回车打开）、
**手动输入数据**（顶栏 ✏️，自己敲一串数字喂给算法，个数 2~12、每个值 1~999）、
**学习笔记**（一个用户对一个算法一条，内容清空即删除）。

## 一、怎么打开（最简单的方式）

**双击项目根目录下的 `启动项目.bat`。**

它会**同时起两个服务**：

| 服务 | 端口 | 作用 |
| --- | --- | --- |
| **后端** | 3000 | 账号、收藏、学习记录、算法元数据（SQLite 数据库，文件在 `server/data/app.db`） |
| **前端** | 5173 | 网页本身（首页 + 算法演示界面） |

黑窗口出现后会自动打开浏览器，网址是：

```
http://localhost:5173/
```

- **打开后先是首页**（`#/`）：一行大字「算法可视化平台」+ 一个「**进入学习-->**」按钮，
  右上角有登录 / 注册入口。**点「进入学习-->」才进算法界面**（地址变成 `#/learn`）。
  首页上那行规模数字（几个大类、几个算法）是**从代码里数出来的**，加算法会自动跟着变。
- **地址写全了是这样**：`#/` 首页、`#/learn` 算法学习界面、`#/favorites` 我的收藏、`#/admin` 后台管理；
  **空地址或者写错的地址会回到首页**（不会白屏）。

- 第一次双击需要先安装依赖，大约 1~3 分钟，之后每次启动只要几秒。
- 要关闭服务：直接关掉那个黑窗口（脚本会把后端的 3000 端口一起收掉）。
- 前提：电脑上装过 Node.js（到 <https://nodejs.org/zh-cn> 下载 LTS 版本，一路下一步即可）。
  **后端不需要装数据库** —— 用的是 Node 自带的 SQLite，数据库就是 `server/data/app.db` 这一个文件。
- **管理员账号**：`admin` / `（已移除的旧口令）`（第一次启动时自动创建）。**正式使用请登录后立刻改密码。**
- ✅ **不想双击 bat 也行：命令行里直接 `npm run dev` 就够了** —— 它现在会**自动把后端一起带起来**（启动时先探一下 3000 端口：**已经在跑就跳过**，没跑就自己起一个，日志里写清楚是哪一种；所以 `启动项目.bat` 依旧可用，不会重复起）。**Vite 一关，它起的那个后端也一起收掉**，不留孤儿进程。
- 想回到"只跑前端"的老样子：`NO_AUTO_SERVER=1 npm run dev` —— 那样登录 / 收藏 / 后台会报"连不上后端服务"（接口 404），但**看算法、播放动画完全不受影响**，因为算法本来就在浏览器里跑。

## 二、手工命令（开发者用）

```bash
npm install       # 安装依赖
npm run dev       # 启动前端 —— http://localhost:5173/（会自动把后端 3000 一起带起来；NO_AUTO_SERVER=1 可关掉）
npm run server    # 只启动后端 —— http://localhost:3000/api（前后端分开跑时用）
npm run build     # 生产构建（会先跑类型检查）
npm test          # 跑全部自动化测试：前端 782 项（Vitest）+ 后端 102 个用例（node:test）= 884 项
npm run test:server   # 只跑后端那 102 个用例（server/test/，跑在临时库 + 随机端口上）
npm run typecheck
```

> `npm run build` 之后，`dist/` 存在时**后端会自动同时提供网页和接口**，只用一个端口 3000 就能访问完整系统。

## 三、怎么用

| 操作 | 效果 |
| --- | --- |
| **首页（`#/`）** | 打开网站看到的第一屏：大字标题 + 「**进入学习-->**」按钮（点了进算法界面 `#/learn`）。首页**没有算法选择器那条顶栏**，但右上角一样能登录 / 注册 |
| **下一步** | 代码高亮往下走一行，右侧柱子按这一步的动作变化 |
| **上一步** | 代码高亮退回上一行，柱子也退回上一步的样子 |
| **重置** | 回到最开始的状态（第 1 步） |
| **播放 / 暂停** | 自动连续播放，可配合速度档位（0.5× / 1× / 2× / 4×） |
| **进度条** | 直接拖到任意一步（步骤序列是全量可索引的，跳转是即时的） |
| **算法（两级选择）** | 点顶部「排序 / 冒泡排序 ▾」展开：**左列选大类**（线性表 / 栈 / 队列 / 数组与矩阵 / 串 / 树与二叉树 / 图 / **动态规划** / 查找 / 排序），**右列按子类分组列出该大类下的算法**及复杂度；小类标题是**白色加粗 + 琥珀色高亮条** |
| **🔍 搜索算法** | 同一个面板顶部的搜索框：**跨全部大类**模糊搜**算法名称和 id**（比如敲「背包」或「dp-」），命中的字会标出来。键盘 **↑ ↓** 选择、**回车**打开、**Esc** 第一次清空搜索、第二次才关面板。（框前有一个 🔍 图标、框上有 `aria-label="搜索算法"`，所以**不再放那段很长的 placeholder 灰字** —— 提示已经由图标和无障碍标签承担，灰字只会挤占输入区） |
| **✏️ 手动输入数据** | 顶栏那个铅笔按钮：自己敲一串数字（例如 `5, 2, 9, 1, 7, 3`）喂给当前算法。**个数 2~12、每个值 1~999**，写错了给中文提示。这是"我想验证自己心里那个例子"用的。弹窗里的示例**只作展示、不能点**（示例在顶部提示和输入框占位符里已经出现两次，再放一个能点的按钮会覆盖用户已经敲进去的内容） |
| **上一个 / 下一个算法** | 页脚解说栏右侧两个按钮，可在**同一个大类内**前后切换算法（边界按大类划分，中间显示"线性表 · 第 3 / 14 个"） |
| **进栈 / 出栈动画** | 栈类算法里，新元素**从上方滑入**，出栈元素**向上滑出**，`top` 指针也跟着滑上去（横排的板子则是左右滑动） |
| **数据规模 / 随机数据 / 示例数据** | 换数据量、换一组随机数据、回到示例数据 |
| **⭐ 收藏（需要登录）** | 算法面板标题栏的星标，点亮 / 取消；状态存在**服务器**上，换电脑登录同一账号仍然在 |
| **👤 登录 / 注册** | 顶栏右上角（**首页右上角也有**）。用户名 3~20 位（字母数字下划线），密码至少 6 位；昵称 1~20 字 |
| **🖼 更换头像（需要登录）** | 右上角菜单里的「更换头像」。选一张图片，**会在浏览器里自动居中裁方、缩到 128×128、压成 JPEG 再上传**（原图几 MB，存进数据库的只有几 KB）；也可以点「恢复默认」清除头像，顶栏就显示**昵称的第一个字** |
| **我的收藏 / 学习记录** | 右上角菜单进入（`#/favorites`）。学习记录 = 每个算法"打开过几次、最多看到第几步、一共几步" |
| **📊 学习报告（需要登录）** | 顶栏右侧「学习报告」按钮（`#/report`）：**覆盖率环**（学过多少个 / 一共 101 个）、**按大类分布条**、**打开次数 Top 10**、**最近学习**、**看得最完整的几个**。图表**全是 SVG / CSS 手画的，没有引入任何图表库**；页面上每个数字都由 `src/core/report.ts` 的**纯函数**从学习记录算出来。⚠️ 口径：**打开不算学过，至少看到第 2 步才算** |
| **📝 学习笔记（需要登录）** | 笔记面板在**左栏、代码框的正下方**（宽度和代码框一样，**不占右边动画区的高度**；笔记再长也不会把代码框压没）：给**当前这个算法**写自己的理解 / 易错点（最多 2000 字）。**一个用户对一个算法只有一条**（再写就是更新），**把内容清空再保存 = 删除这条笔记**；笔记是私人数据，别人读不到 |
| **后台管理（仅管理员）** | 右上角菜单进入（`#/admin`），两个标签页：**用户管理**（搜索 / 改昵称 / 改角色 / 禁用 / 重置密码 / 删除 / **清空某个人的头像**）和**算法管理**（增删改查 + 上架下架 / 新增时大类可选 10 个，含**动态规划**）。 |

键盘快捷键：`空格` 播放/暂停，`←` `→` 单步，切换输入框时自动屏蔽。

> **进入算法界面（`#/learn`）时不会默认帮你选一个算法。** 第一次进来是**空状态**：
> 一句「**先选一个算法开始学习吧**」+ 一个「**看看有哪些算法**」按钮（点了就展开顶栏的算法选择器）。
> 选了算法之后，代码区 / 动画区 / 笔记面板 / 控制条才出现。
> 为什么不默认选中冒泡排序：那次"自动选中"会被学习记录当成**一次真实学习**记进数据库
> （用户根本没看，记录里却多出一条）。这条已经固化成 6 条常驻回归用例（`src/stores/learnSelection.spec.ts`）。
>
> 顺带一句：**打开界面点两下就能发现的问题，自动化测试不一定拦得住** —— 用户肉眼找出的十几处
> "动画在说假话"（板子上的字指向一个不存在的东西、动画干了代码没干的事……）全部躲过了当时已有的
> 800 多条测试，而其中**能自动化的部分现在已经固化成 33 条新用例**（见第五节「测试」那一行）。

### 游客能做什么、登录能做什么

| 身份 | 能干什么 |
| --- | --- |
| **游客** | 看全部 101 个算法与动画、单步 / 播放 / 换数据规模、**手动输入数据**、**搜索算法** —— **和以前完全一样**。点收藏时会弹登录框。 |
| **登录用户** | 游客的全部 + 收藏 / 取消收藏 + 学习记录 + **看学习报告** + **给算法写学习笔记** + 改自己的昵称和密码（**改密码后其它设备上的登录立刻失效**，当前这台保持登录）+ **换自定义头像**（不想用了可以恢复成昵称首字）。 |
| **管理员** | 登录用户的全部 + 后台：概览统计（用户数 / 算法数 / 收藏数 / 今日新增）、用户管理、算法管理（含上架下架），还能**清空某个用户的头像**。 |

**几条安全规矩**（都写在服务端代码里，不只是文档里）：密码**不存明文**（加盐哈希）；**权限在服务端查**（普通用户拿着自己的令牌去请求后台接口也是 403，藏按钮只是界面好看）；管理员**不能删自己**、**不能把最后一个管理员删掉或降级**（否则系统锁死）；**用户只能操作自己的收藏、学习记录和笔记**；**改密码会作废其它设备上的旧登录会话**（当前这台保留；管理员在后台重置密码则是全清）；**头像只收图片的 data URL**（PNG / JPEG / WebP / GIF，正文不超过 200KB，**不收 SVG** —— SVG 里能藏脚本），非法内容直接 400 且**不写进数据库**；**笔记正文最多 2000 字**，超出直接 400；所有 SQL 都用参数绑定防注入。

### 已实现的算法（10 个大类 / 39 个子类 / 101 个算法）

大类的先后 = 选择器左列从上到下的顺序：**线性表 → 栈 → 队列 → 数组与矩阵 → 串 → 树与二叉树 → 图 → 动态规划 → 查找 → 排序**。

| 大类 | 子类 | 算法 | 可视化形式 |
| --- | --- | --- | --- |
| **线性表** | 顺序表 | 插入、删除、按值查找、按位查找 | **单元格表格**，超出表长的格子是虚线空位 |
| | 单链表 | 头插法建表、尾插法建表、按序号查找、按值查找、插入、删除 | **结点 + 箭头图**，头结点、命名指针（p / s / q…） |
| | 双链表 | 插入、删除 | 结点 + 箭头图，每两个结点之间一对**反向箭头** |
| | 循环链表与环 | 判断链表是否有环、寻找环的入口 | 结点 + 箭头图，**绿色回头箭头**表示成环，环入口标绿 |
| **栈** | 顺序栈 | 进栈、出栈 | **竖排格子**，`top` 指针，栈空时不画指针 |
| | 链栈 | 进栈、出栈 | 结点 + 箭头图（只允许在头部增删） |
| | 共享栈 | 共享栈 | **横排格子 + 两端相向生长的两个指针** |
| | 栈的应用 | 括号匹配、中缀转后缀、后缀表达式求值 | 竖排栈 + **纸带**（正在扫描的字符串，当前字符高亮） |
| | 栈与递归 | 递归求阶乘 | 竖排格子画**调用栈**的每一层，压栈 / 回代都看得见 |
| **队列** | 循环队列 | 入队、出队 | **环形布局**，`front` / `rear` 指针绕圈 |
| | 链队列 | 入队、出队 | 结点 + 箭头图，`front` / `rear` 命名指针 |
| **数组与矩阵** | 特殊矩阵 | 对称矩阵、三角矩阵、对角矩阵的压缩存储 | **左边原矩阵 + 右边压缩表**，定位时两块板子同步高亮，换算式写在代码里 |
| | 稀疏矩阵 | 三元组表、十字链表 | 三元组表是 `(行,列,值)` 三列网格；十字链表把结点摆在其 `(i,j)`，用**橙色 right / down 连线**串行链和列链。数据规模按"最接近矩形"的整数边长摆（6 个数 → 2×3），不丢数据也不补空格 |
| **串** | 模式匹配 | BF 暴力匹配 | **两条纸带**：模式串缩进到本趟起点下面，一眼看出它怎么在主串上滑动；KMP 另配 next 数组板 |
| | KMP算法匹配 | 求 next 数组、求 nextval 数组、KMP 算法 | 模式串板（带 i / j 指针）+ next / nextval 数组板，逐位填出来 |
| **树与二叉树** | 二叉树的遍历 | 先序 / 中序 / 后序（各有递归与非递归）、层次遍历 | **树形图**（左孩子天然在左），非递归版把栈 / 队列里的结点挂成小标签 |
| | 线索二叉树 | 中序线索化、线索二叉树的遍历 | 孩子是实线、**线索是橙色虚线**，一眼分清 |
| | 树与森林 | 双亲表示法、孩子表示法、孩子兄弟表示法、树的遍历（先根 / 后根）、森林的遍历、树转二叉树 | 双亲表示法用**向上虚线**，孩子兄弟表示法就是二叉树的形态 |
| | 哈夫曼树 | 构造、哈夫曼编码 | 构造用森林（多棵树）演合并，上方还有一块"游离结点池"；编码用表格列出每个字符的 01 串 |
| | 并查集 | Find（查找根 + 路径压缩）、Union（合并集合） | 树形图 + 向上虚线，`sub` 显示秩 |
| **图** | 存储结构 | 邻接矩阵、邻接表、十字链表、邻接多重表 | **顶点 + 带权边的网络图**，另配一块板子画邻接矩阵 / 邻接表 / 弧结点表 / 边结点表，填表和画图同步高亮 |
| | 遍历 | 深度优先搜索 DFS（递归）、深度优先搜索 DFS（非递归）、广度优先搜索 BFS | 网络图，访问到的顶点依次标绿；递归版另挂**递归调用栈**，非递归版挂**栈**，BFS 挂**队列**（顶点旁标访问次序） |
| | 拓扑排序 | 拓扑排序（AOV 网） | 网络图，顶点旁标**当前入度**，入度为 0 的高亮，输出的顶点依次标绿 |
| | 最小生成树 | Prim、Kruskal | 网络图 + 板子：Prim 用 `lowcost[]` 板（顶点写"已选"），Kruskal 用**按权值排序的边表** + **并查集分组板**（选中的边变绿、会成环的变红） |
| | 最短路径 | Dijkstra、Floyd | 网络图 + 板子：Dijkstra 用 `dist[]` 板（已确定的顶点变绿），Floyd 用**距离矩阵**逐轮填出所有顶点对的最短路 |
| | 关键路径 | 关键路径（AOE 网） | 网络图 + 板子：先按拓扑序正推 `ve`、再倒推 `vl`，活动表列出每条活动的 `e / l / l-e`，`e = l` 的标成关键活动 |
| **动态规划** | 背包问题 | 0-1 背包 | **二维 dp 表一格一格填出来**：第 0 行 / 第 0 列是边界 0（偏暗），正在算的格子紫色高亮，两个来源格子（不选 / 选）用红指针指着；表下面另挂一块"物品清单"小板，最后回推出"选了哪些物品"。**复用画矩阵那套通用格子板，没有新增渲染器** |
| | 双串模型 | 最长公共子序列、编辑距离 | 同样是**二维 dp 表**：LCS 两个字符相等就斜着取左上角 + 1、不相等就取"上"和"左"里大的那个；编辑距离对"删 / 插 / 换"三个来源格子取最小再加 1 —— **指针上直接写着这一步在做哪种操作**，格子右下角标着它的 `i, j`，方便对着代码公式核 |
| **查找** | 线性表的查找 | 顺序查找、折半查找、分块查找 | 前两个是柱状图 + **目标值虚线**，候选区间外的柱子**变暗**；分块查找是柱状图 + **索引表**（先查索引再查块内） |
| | 二叉排序树 | 插入、查找、删除 | 树形图，删除会依次演到"叶子 / 单孩子 / 双孩子"三种情况 |
| | 平衡二叉树 | AVL 的 LL / RR / LR / RL 旋转、红黑树·插入与调整 | AVL 每个结点显示**平衡因子**，失衡点标红，参与旋转的结点标紫；红黑树**红结点红底、黑结点深底**（结点自带颜色），三种调整情况都演到 |
| | 多路平衡查找树 | B 树·插入与查找、B+ 树·插入与查找 | 树形图，**一个框里装多个关键字**（自动加宽），演到结点分裂与级联分裂；B+ 树的关键字全在叶子层，叶子之间用一条虚线链串起来 |
| | 散列表 | 哈希表查找 | **格子板**画散列表与冲突链 |
| **排序** | 插入类排序 | 直接插入排序、折半插入排序、希尔排序 | 柱状图（颜色区分 比较中 / 交换中 / 已就位）；希尔排序在变量栏显示 **gap**，同一组的元素一起高亮 |
| | 交换类排序 | 冒泡排序、快速排序 | 柱状图；快速排序再加**候选区间**标出正在划分的那一段，递归子区间依次演 |
| | 选择类排序 | 选择排序、堆排序、建堆（自下而上）、堆调整（向下调整 / 筛选） | 柱状图；堆排序用候选区间标出堆的范围，反复"换堆顶 / 堆减一 / 向下调整"；建堆 / 堆调整换成**数组板**（数组就是堆的层序存储），孩子下标公式写在提示里 |
| | 归并类排序 | 归并排序 | 柱状图 + 候选区间标出正在合并的两段 |
| | 分配类排序 | 计数排序、基数排序 | 柱状图 + **下方板子**：计数排序是**两块板子**（计数数组 / 输出数组），基数排序是**10 个桶**，逐轮分桶再回收 |
| | 外部排序 | 外部排序（多趟归并）、多路平衡归并与败者树、置换-选择排序、最佳归并树 | **场景板**（多趟归并 / 初始归并段）+ **树形图**（败者树 / 最佳归并树） |


> 表里子类的先后就是**代码里的注册顺序**：`getGroupedByCategory` 只把**相邻**的同名子类并成一组，
> 所以同一个子类的算法在 `src/algorithms/index.ts` 里必须连着写（注册表里每一段都标了注释说明这件事）。
> 现在的子类总数是 **39 个**（这一轮新增了「背包问题」和「双串模型」），名字互不重复 —— "同名子类被别的子类隔开、界面上裂成两个同名标题"这个老毛病已经没有了
> （当年「分配类排序」就被「选择类排序」夹断过一次，界面上冒出过两个「分配类排序」标题）。
> 小类标题的样子是**白色加粗 + 左侧琥珀色竖条 + 极淡同色底**（琥珀色取自配色里的"比较中" `#f59e0b`，
> 和"当前选中的算法"的蓝色系刻意分开：标题一眼能扫到，又不会盖过选中项）。

六种可视化形式由算法自己声明（`renderer: 'array' | 'seqlist' | 'linked' | 'scene' | 'tree' | 'graph'`），加算法时选一个即可，渲染器会自动切换。
其中 `scene` 是通用「场景」渲染器：栈、队列、矩阵、压缩表、调用栈、堆、字符串匹配、哈希表、外部排序**和动态规划的二维表**全都归结成"一组格子 + 若干命名指针"，
靠 `boards` 的 `layout`（`row` / `column` / `grid` / `ring`）换形状，`tapes` 用来表示"正在扫描的字符串"；
`tree` 画层级结点图（二叉树 / 多叉树 / 森林 / 并查集），`graph` 画顶点 + 带权边的网络图；
`array` / `tree` / `graph` 这三种都能在**主视图之外再接一块 `boards` 板子**（柱状图下面接计数数组 / 基数排序的桶，树下面接栈和队列，图旁边接 `lowcost[]` / `dist[]` 这些表格）。

> - 折半查找要求输入有序，所以带 `prepareData` 兜底：点「随机数据」也会先排序，不会喂坏数据。
> - 顺序表容量固定为 16，`prepareData` 会留出空位，这样"插入"不会因为表满而失败。

## 五、技术栈

| 层 | 用了什么 | 说明 |
| --- | --- | --- |
| **前端** | Vue 3 · TypeScript · Vite · Pinia · CodeMirror 6 · D3（`d3-scale`）· HTML5 Canvas | 算法在**浏览器里跑**，所以动画与代码高亮的同步不受网络影响 |
| **前端路由** | 自己写的极简 hash 路由（`src/router.ts`，99 行） | 只有 5 个页面（首页 / 算法界面 / 我的收藏 / **学习报告** / 后台），**不引入 vue-router**，保持零新增依赖 |
| **后端** | Node 原生 `node:http` + `node:sqlite` + `node:crypto`（`server/` 4 个文件，约 1481 行） | **一个第三方包都没加**；没有 Express、没有 ORM |
| **数据库** | SQLite（单文件 `server/data/app.db`，6 张表；users 含 `avatar` 列、另有 `notes` 笔记表） | 不用安装、不用配服务，但是真数据库（SQL / 事务 / 索引）；加列用**幂等 `ALTER TABLE`**、加表用**幂等 `CREATE TABLE IF NOT EXISTS`**，老库升级不丢数据 |
| **密码与会话** | `crypto.scrypt` 加盐哈希 + 32 字节随机令牌（7 天） | 密码不存明文；比对用 `timingSafeEqual` |
| **测试** | 前端 Vitest **782 项** + 后端 `node:test` **102 个用例** = **884 项全绿** | 前端管算法步骤序列与播放状态（`algorithms.spec.ts` 734 + `algorithm.spec.ts` 9），另有 6 项是「进入学习不默认选中算法」的回归用例（`learnSelection.spec.ts`）；**这一轮用户点界面点出来的十几处"动画在说假话"全都躲过了原有的测试**，于是新增 5 个针对性 spec（`countSort` 8 / `hashBoard` 7 / `radixBoard` 7 / `shellSort` 5 / `pointerLabels` 6，共 33 项），这 33 项现在还反过来守着那些修复不被改回去，详见《毕业设计答辩-问题与修复清单.md》**五 · 11**；后端管接口：权限边界 / 参数校验 / 数据隔离 / SQL 注入与目录穿越 / 改密码作废其它设备会话 / **头像校验与老库升级** / **笔记的一人一条与越权防护**。`npm test` 前后端一起跑，`npm run test:server` 只跑后端；后端用 `%TEMP%` 临时库 + 随机端口，**不碰** `server/data/app.db` |
| **图表** | **没有图表库** —— 学习报告页的图是手画的 | 覆盖率环是 **SVG** 圆（靠虚线长度表达百分比），大类分布条是 **CSS 宽度百分比**；数字全部由 `src/core/report.ts` 的纯函数算出。为"一个环 + 几条横条"引入几百 KB 的库不划算 |

**取舍要说清楚**：不用框架和 ORM，换来的是"双击就能跑、零安装、故障面小"；代价是路由分发、参数校验、建表都要自己写，而且 SQLite 只适合单机小规模（要上高并发第一件要换的就是它）。详见《毕业设计答辩-问题与修复清单.md》第一部分第 6 条。

## 六、新增一个算法（两步 + 一步对齐）

1. 在 `src/algorithms/` 下新建文件，导出一个 `AlgorithmSpec`：**C++ 展示源码** + **步骤生成器** + `category`（归到哪个大类）。
2. 在 `src/algorithms/index.ts` 的 `algorithmRegistry` 里加一行。
3. ⚠️ **再去 `server/db.mjs` 的 `SEED_ALGORITHMS` 里补一条同样的元数据**（`algo_key` / 名称 / 大类 / 子类 / 难度 / 简介），位置要和前端注册顺序一致。

两级选择器、播放器、代码面板、Canvas 渲染器、控制器**都不需要改动**。

> **第 3 步为什么省不掉**：前端是 `.ts`、后端是 `.mjs`，**运行时谁也读不到谁**，所以算法的"元数据"是两份
> **手工维护**的清单。只改前端的话，首页 / 报告页的规模数字是 101，而后台算法列表、概览统计、
> `GET /api/algorithms` 还是旧条数，三者对不上。这一轮就真的错了一回 ——
> 动态规划那批只改了前端（前端 101 / 后端 98），而且后端那句"合法大类"白名单里也忘了加 `dp`，
> 管理员在后台一选「动态规划」就被 **400** 拒。教训见《毕业设计答辩-问题与修复清单.md》**六 · 1**：
> **并行开发时，"跨两端的那个数字 / 那个枚举"是没人拥有的，收尾必须专门有人对齐一次。**
> 对齐的验法是实测的：两边条数相等、`algo_key` 的**集合与顺序完全一致**、名称 / 大类 / 子类零处不一致。
> （顺带一句：后端种子是**幂等补齐**的 —— 每次启动只补缺的、绝不覆盖后台改过的字段。
> 好处是老库会自动补上新算法；副作用是**后台删掉一个"种子里的"算法，下次启动会被补回来**，
> 想永久隐藏请用「**下架**」而不是删除。）

> 另一处例外是**用到新结构字段**的算法：B 树 / B+ 树要在一个结点里装多个关键字、红黑树要给结点指定颜色，
> 这两种情况得给渲染器补上 `keys` / `color` 两个字段（算法本身、播放器、选择器照样不用动）。
> 计数排序 / 基数排序要"柱状图下面接板子"，也是把树、图早就在用的那套板子机制接到柱状图上，没有新造一套。
> **动态规划那 3 个连字段都没补** —— 它填的就是一张二维表，直接复用了画矩阵用的「通用格子板 + 网格布局」，
> **一个渲染器都没新增**（原先估的是"需要再加一个二维表格渲染器"，动手时发现现成能力就能覆盖）。

如果要开一个**新的大类**（比如"动态规划"），在 `src/core/categories.ts` 的 `CATEGORIES` 里加一项即可，选择器会自动多出一列 ——
**但别忘了第 3 步**：`server/api.mjs` 的 `CATEGORY_NAMES` 白名单里也要有这一项，否则管理员在后台选它会被 400 拒。
要开一个**子类**（比如"栈""队列""散列表""背包问题"），只要在 spec 里写 `group: '栈'`，同名且注册位置挨在一起的会自动归到一组 ——
**中间不能插进别的子类**，否则界面上会把一个标题裂成两个（`getGroupedByCategory` 只合并相邻的同名组）。

校验规则也是**按数据结构区分的**：数组要求"长度恒定 + 多重集守恒"，顺序表允许长度变化但不得超过容量，链表则校验 next/prev/head/pointers 的引用是否自洽 —— 因为不同数据结构的不变量本来就不一样。

> 代码面板上显示的是 **C++ 风格源码**（与教材一致），它不参与执行；真正产出步骤序列的是紧挨着的 TypeScript 生成器，两者逐行一一对应。

生成器里每个 `yield` 就是一个可展示步骤，必须带上它在 **C++ 源码里的行号**：

```ts
// C++ 第 4 行：if (a[j] > a[j + 1]) {
yield { line: 4, action: 'compare', array: a, indices: [j, j + 1], comment: `比较 a[${j}] 与 a[${j + 1}]` }
```

行号写错、忘了拷快照、元素弄丢、解说为空 —— `engine.ts` 的校验器和单元测试会直接报错，不会静默显示错误内容。
