# 算法可视化平台

一个用于《数据结构与算法》教学的可视化演示平台：**左侧显示算法源码并高亮当前执行行，右侧用柱状图动画展示数据变化，两者严格同步**，支持「上一步 / 下一步 / 播放 / 重置」。

---

## 一、怎么打开（最简单的方式）

**双击项目根目录下的 `启动项目.bat`。**

黑窗口出现后会自动打开浏览器，网址是：

```
http://localhost:5173/
```

- 第一次双击需要先安装依赖，大约 1~3 分钟，之后每次启动只要几秒。
- 要关闭服务：直接关掉那个黑窗口。
- 前提：电脑上装过 Node.js（到 <https://nodejs.org/zh-cn> 下载 LTS 版本，一路下一步即可）。

## 二、手工命令（开发者用）

```bash
npm install     # 安装依赖
npm run dev     # 启动开发服务器 —— http://localhost:5173/
npm run build   # 生产构建（会先跑类型检查）
npm test        # 运行单元测试
npm run typecheck
```

## 三、怎么用

| 操作 | 效果 |
| --- | --- |
| **下一步** | 代码高亮往下走一行，右侧柱子按这一步的动作变化 |
| **上一步** | 代码高亮退回上一行，柱子也退回上一步的样子 |
| **重置** | 回到最开始的状态（第 1 步） |
| **播放 / 暂停** | 自动连续播放，可配合速度档位（0.5× / 1× / 2× / 4×） |
| **进度条** | 直接拖到任意一步（步骤序列是全量可索引的，跳转是即时的） |
| **算法（两级选择）** | 点顶部「排序 / 冒泡排序 ▾」展开：**左列选大类**（线性表 / 栈 / 队列 / 数组与矩阵 / 串 / 树与二叉树 / 图 / 查找 / 排序），**右列按子类分组列出该大类下的算法**及复杂度；小类标题是**白色加粗 + 琥珀色高亮条** |
| **上一个 / 下一个算法** | 页脚解说栏右侧两个按钮，可在**同一个大类内**前后切换算法（边界按大类划分，中间显示"线性表 · 第 3 / 14 个"） |
| **进栈 / 出栈动画** | 栈类算法里，新元素**从上方滑入**，出栈元素**向上滑出**，`top` 指针也跟着滑上去（横排的板子则是左右滑动） |
| **数据规模 / 随机数据 / 示例数据** | 换数据量、换一组随机数据、回到示例数据 |

键盘快捷键：`空格` 播放/暂停，`←` `→` 单步，切换输入框时自动屏蔽。

> 表里子类的先后就是**代码里的注册顺序**：`getGroupedByCategory` 只把**相邻**的同名子类并成一组，
> 所以同一个子类的算法在 `src/algorithms/index.ts` 里必须连着写（注册表里每一段都标了注释说明这件事）。
> 现在的子类总数是 **37 个**，而且 37 个名字互不重复 —— "同名子类被别的子类隔开、界面上裂成两个同名标题"这个老毛病已经没有了
> （当年「分配类排序」就被「选择类排序」夹断过一次，界面上冒出过两个「分配类排序」标题）。
> 小类标题的样子是**白色加粗 + 左侧琥珀色竖条 + 极淡同色底**（琥珀色取自配色里的"比较中" `#f59e0b`，
> 和"当前选中的算法"的蓝色系刻意分开：标题一眼能扫到，又不会盖过选中项）。

六种可视化形式由算法自己声明（`renderer: 'array' | 'seqlist' | 'linked' | 'scene' | 'tree' | 'graph'`），加算法时选一个即可，渲染器会自动切换。
其中 `scene` 是通用「场景」渲染器：栈、队列、矩阵、压缩表、调用栈、堆、字符串匹配、哈希表、外部排序全都归结成"一组格子 + 若干命名指针"，
靠 `boards` 的 `layout`（`row` / `column` / `grid` / `ring`）换形状，`tapes` 用来表示"正在扫描的字符串"；
`tree` 画层级结点图（二叉树 / 多叉树 / 森林 / 并查集），`graph` 画顶点 + 带权边的网络图；
`array` / `tree` / `graph` 这三种都能在**主视图之外再接一块 `boards` 板子**（柱状图下面接计数数组 / 基数排序的桶，树下面接栈和队列，图旁边接 `lowcost[]` / `dist[]` 这些表格）。

> - 折半查找要求输入有序，所以带 `prepareData` 兜底：点「随机数据」也会先排序，不会喂坏数据。
> - 顺序表容量固定为 16，`prepareData` 会留出空位，这样"插入"不会因为表满而失败。

Vue 3 · TypeScript · Vite · Pinia · CodeMirror 6 · D3（`d3-scale`）· HTML5 Canvas

## 六、新增一个算法（两步）

1. 在 `src/algorithms/` 下新建文件，导出一个 `AlgorithmSpec`：**C++ 展示源码** + **步骤生成器** + `category`（归到哪个大类）。
2. 在 `src/algorithms/index.ts` 的 `algorithmRegistry` 里加一行。

两级选择器、播放器、代码面板、Canvas 渲染器、控制器**都不需要改动**。

> 唯一的例外是**用到新结构字段**的算法：B 树 / B+ 树要在一个结点里装多个关键字、红黑树要给结点指定颜色，
> 这两种情况得给渲染器补上 `keys` / `color` 两个字段（算法本身、播放器、选择器照样不用动）。
> 计数排序 / 基数排序要"柱状图下面接板子"，也是把树、图早就在用的那套板子机制接到柱状图上，没有新造一套。

如果要开一个**新的大类**（比如"动态规划"），在 `src/core/categories.ts` 的 `CATEGORIES` 里加一项即可，选择器会自动多出一列。要开一个**子类**（比如"栈""队列""散列表"），只要在 spec 里写 `group: '栈'`，同名且注册位置挨在一起的会自动归到一组 —— **中间不能插进别的子类**，否则界面上会把一个标题裂成两个（`getGroupedByCategory` 只合并相邻的同名组）。

校验规则也是**按数据结构区分的**：数组要求"长度恒定 + 多重集守恒"，顺序表允许长度变化但不得超过容量，链表则校验 next/prev/head/pointers 的引用是否自洽 —— 因为不同数据结构的不变量本来就不一样。

> 代码面板上显示的是 **C++ 风格源码**（与教材一致），它不参与执行；真正产出步骤序列的是紧挨着的 TypeScript 生成器，两者逐行一一对应。

生成器里每个 `yield` 就是一个可展示步骤，必须带上它在 **C++ 源码里的行号**：

```ts
// C++ 第 4 行：if (a[j] > a[j + 1]) {
yield { line: 4, action: 'compare', array: a, indices: [j, j + 1], comment: `比较 a[${j}] 与 a[${j + 1}]` }
```

行号写错、忘了拷快照、元素弄丢、解说为空 —— `engine.ts` 的校验器和单元测试会直接报错，不会静默显示错误内容。

详细的设计说明与答辩讲稿见 **《毕业设计答辩说明书.md》**。
